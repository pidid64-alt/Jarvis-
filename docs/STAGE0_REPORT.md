## 1. Что это сейчас и как устроено

«Jarvis Control Core» — голосовое управление машиной по принципу **белого списка**:

```
Хоткей Super+J / Win+J   ─┐
“Джарвис” (wakeword.py)  ─┴─► jarvis.py (демон) ─► whisper.cpp STT :8081
                                     │
                                     ├─► commands.json / commands-win.json  (фразы → статичные shell-команды)
                                     ├─► scripts/*.sh | scripts_win/*.ps1   (54 + 46 хелперов)
                                     ├─► LLM (OpenAI-совместимый: OmniRoute / OpenRouter) — необязательный разбор свободной речи
                                     └─► Piper TTS :5000 ─► paplay / winsound
```

Сильная сторона замысла: **распознанный текст никогда не становится shell-командой** — он лишь выбирает один из заранее написанных шаблонов. Это надо сохранить в новой версии.

Сопровождающие процессы: `autonomy.py` (8 read-only проверок по расписанию → очередь `inbox.json` → озвучка), `wakeword.py` (постоянное слушание слова), `hotkey-win.py`, `jarvis-trigger.sh/.py`.

### 2.2 Голос

- **STT**: `whisper.cpp` (`whisper-server`, модель `ggml-base-q5_1`, ~57 МБ) — HTTP `:8081`; запись через `parecord` (Linux) / `sounddevice` (Windows); VAD `webrtcvad` с pre-roll, ожиданием начала речи, потолком 12 с.
- **TTS**: Piper `ru_RU-dmitri-medium` (61 МБ) через `http_server :5000`; постобработка текста (`tts_norm.py`): проценты, размеры `3.6Gi`, даты, время, английский uptime → русская речь.
- **Слово-активатор**: `openWakeWord` («Джарвис», модели `.onnx`/`.tflite` в репозитории), отдельный резидентный процесс, гистерезис 3 кадра.
- **Хоткей**: Super+J (XFCE `xfconf-query`), Win+J (`RegisterHotKey` через Win32, без прав администратора).

### 2.3 Провайдеры моделей и API

- LLM: OpenAI-совместимый `chat/completions` через `requests` (`llm_client.py`), ключ из env, `response_format=json_object`, ретраи 1, таймаут 8 с. Парсер `llm_parser.py` умеет 4 действия: `command`, `speak`, `ask`, `search` (до 4 действий на реплику). В промпт уходят только `id/description/tags` команд — не shell-тела.
- Веб-поиск: `ddgs` (DuckDuckGo без ключа) + суммаризация LLM или открытие браузера.
- Локальные проверки здоровья: `/proc`, sysfs, `sensors` (Linux), ctypes/`Get-CimInstance` (Windows).

### 3.2 Тормозит

- **Задержка ответа**: измеренная в проектной документации медиана LLM-маршрута 3.9 с, p90 10.2 с, max 18.5 с (35 замеров); плюс STT и запись. Точный fast-path спасает только «дословные» фразы.
- **Последовательная обработка**: один `processing_lock`, один поток. Пока идёт озвучка (`speak()` блокирует до 30 с таймаута + воспроизведение), новый триггер **молча теряется** (`on_signal` при занятом локе ничего не делает, `jarvis.py:1025-1029`).
- **Резидентная память**: `whisper-server` 150–250 МБ + `piper-server` 150–250 МБ + `wakeword` 50–80 МБ + ядро/автономность ≈ **350–600 МБ постоянно** на машине с 4 ГБ. Ничего не грузится лениво, ничего не выгружается в простое.
- **`autonomy`** каждую минуту тикает и порождает подпроцессы (в т.ч. `sensors -j`, `journalctl`), независимо от того, есть ли что проверять.
- **Запись в одном процессе с обработкой**: `record_audio` держит поток до 12 с.

### 3.3 Нельзя расширять

- **Монолит `jarvis.py` (1130 строк)**: запись, VAD, STT, TTS, матчинг, исполнение, LLM-маршрут, диктовка, inbox, демон — всё в одном модуле; GUI к такому не подключить без переписывания.
- **Навык = запись в JSON на 327 элементов**, без описания прав, без проверки схемы, без тестов: опечатка в `command` обнаруживается только при попытке произнести фразу.
- **Нет модели прав**: `dangerous`/`confirm` есть у 7 команд из 327, при этом `clean_temp` = `sudo rm -rf /tmp/*`, `empty_trash` = `rm -rf …`, `focus_mode` (убивает discord/telegram/spotify) идут **без подтверждения**. Разграничения «что навыку разрешено» нет вообще.
- **Дубликаты фраз** в каталоге (4 группы, напр. «открытые порты» у двух id) → матчер честно считает это неоднозначностью и отказывает.
- **Копипаста инфраструктуры**: `_win_no_window_kwargs` продублирован в 4 файлах (`jarvis.py`, `autonomy.py`, `health_checks.py`, `platform_support.py`), `STATE_DIR`/`BASE_DIR` объявлены заново в 5 модулях, `wakeword.py` заводит свои `BASE_DIR/STATE_DIR`, `autonomy.py` — свои.
- **Платформенные ветки размазаны** по `jarvis.py`/`wakeword.py`/`health_checks.py` (CLAUDE.md сам признаёт это правило и оно уже нарушено).
- **Нет i18n**: строки по-русски хардкодом в 15+ модулях; `tts_norm.py` умеет только русский.
- **Нет CI, нет линтера, нет схемы состояний**: `__pycache__/*.pyc` (Python 3.14!) закоммичены; `commands.json.backup` (219 команд) лежит мёртвым грузом.

### 3.4 Секреты

- Само место хранения выбрано верно (`~/.config/jarvis/env`, 600), ключ читается из env и не печатается в лог.
- Проблемы рядом: (а) в истории проекта ключ **был захардкожен в systemd-юнитах и в документации** — `docs/superpowers/*` до сих пор содержат инструкцию с извлечением ключа из `~/.claude/settings.json` и примером `OMNIROUTE_API_KEY=sk-…`; (б) `llm_client.py:88` логирует первые 200 символов тела ответа при ошибке HTTP — при некоторых прокси туда попадает эхо запроса; (в) нет ни маскирования в логах, ни единого места для «отчёта без секретов», ни хранения ключей через интерфейс (пользователь правит `.env` руками); (г) `autonomy.py:392` — хардкод имени переменной.

### 3.5 Дублирование данных

- 3 разных места, где описана одна и та же команда для Linux/Windows (JSON ×2 + скрипты в двух каталогах), синхронизируются вручную: 54 linux-команды отсутствуют в Windows-версии, 1 — только в Windows.
- `commands.json.backup` (71 КБ) — снимок 219 команд, нигде не используется, но попадает в каждый клон.
- Модели (118 МБ) в git — при 4 ГБ RAM и слабом канале это ещё и медленный клон.

## 5. Предлагаемая архитектура (Этап 1)

### 5.1 Слои

```
jarvis/                         единый пакет + одна команда запуска `jarvis`
├─ core/            ядро: оркестратор, маршрутизатор, права, реестр навыков, события, ошибки
├─ skills/          навыки-плагины: 1 навык = 1 папка (skill.json + handler)
├─ providers/       провайдеры: llm/, stt/, tts/, audio/, search/, notify/
├─ interfaces/      gui/, cli, daemon(трей+хоткей), api (локальный HTTP+JSON)
├─ platform/        linux.py | windows.py — всё платформенное здесь и только здесь
└─ config/          config.toml, .env.example, i18n/ru.json, i18n/en.json
```

Правила, которые проверяются тестами и линтером:
- `interfaces/*` не содержит логики — только вызовы ядра через API/клиент.
- `core/*` не знает про GUI, системы координат и ОС (только через `platform/`).
- `skills/*` не лезет в сеть/файлы/процессы напрямую — через разрешения, выданные ядром.

### 5.2 Навыки как плагины

```
skills/volume/skill.json      { id, name, description, phrases[], examples[],
                                permissions: { shell: [шаблоны], files: false,
                                               network: false, notify: true },
                                confirm: false }
skills/volume/handler.py      def handle(intent, ctx) -> Reply
```
Добавление навыка = добавить папку. Ядро само найдёт её при старте, покажет в GUI («Навыки»: вкл/выкл, описание, права) и в `jarvis doctor`.
Ленивая загрузка: импортируется только тот навык, который нужен для текущей фразы.
Каталог старых команд станет одним сгенерированным навыком-каталогом (по группам), а не 327 папками.

### 5.3 Один конфиг, секреты отдельно

- `config/config.toml` — единственный файл настроек (TOML: комментарии, типы), ссылки на секреты вида `api_key = "${JARVIS_LLM_KEY}"`.
- `.env` (600, gitignored) — только секреты. GUI пишет их туда, ядро читает в память; **ни в лог, ни в GUI, ни в консоль значение не выводится** (в логах и в «копировать для отчёта» — маска `sk-…abcd`).
- `jarvis doctor` проверяет: есть ли `.env`, права 600, ключ виден, но не печатается.

### 5.4 Единый способ вызова

- `jarvis` — одна команда: `jarvis run` (демон+трей), `jarvis ask "текст"`, `jarvis doctor`, `jarvis skills`, `jarvis logs`, `jarvis gui`, `jarvis install/uninstall`.
- Один хоткей и одно слово-активатор (настраиваются), одинаковое поведение из терминала, GUI и голоса: всё идёт через один `Assistant.handle(text) -> Reply`.

### 5.5 Права и подтверждения

- Режим ограниченных прав: навык без права `shell` не может запускать команды, даже если очень хочет.
- Опасные навыки (`poweroff`, `reboot`, `system_update`, `rm`, отправка сообщений от вашего имени) требуют подтверждения **всегда**, независимо от канала (голос → «Скажи да», GUI → диалог, CLI → `--yes`).
- Подтверждение может прийти из другого интерфейса: спросили голосом — можно подтвердить в GUI (единый `ConfirmationBroker`).

### 5.6 Ошибки, таймауты, повторы

- Единый `JarvisError` + пользовательские тексты в `core/messages.py` (i18n), подробности — в лог с ротацией.
- Все сетевые вызовы провайдеров: таймаут → 1–2 повтора с backoff → понятное сообщение + «провайдер недоступен N секунд» (circuit breaker), чтобы не ждать 30 с на каждой фразе.
- Никаких молчаливых `except: return ""`: ошибка → ответ пользователю + запись в журнал.

### 5.7 GUI

- Локальный HTTP+JSON API на `127.0.0.1` (stdlib, токен в файле состояния) — контракт между ядром и любым интерфейсом, версионированный (`/api/v1`).
- Окно: ввод + история + кнопка микрофона + индикатор состояния (слушает/думает/отвечает/ошибка) + кнопка «стоп».
- Страницы: «Диалог», «Навыки», «Настройки», «Журнал», «О программе» (с лицензиями и упоминанием сторонних проектов).
- Трей (pystray) + хоткей; закрытие окна → сворачивание в трей.
- Тексты из `i18n/*.json`, тема светлая/тёмная.

### 5.8 Миграция

`jarvis migrate` (одна команда):
1. копирует всё старое в `legacy/` + `~/jarvis-legacy-backup-<дата>/`;
2. конвертирует `config.json` + `wakeword_config.json` → `config.toml`;
3. конвертирует `commands*.json` → навык-каталог (фразы сохраняются 1:1, `$HOME/jarvis` → `{base}`, теги → права), `autonomy.json` → секцию расписания;
4. переносит `~/.config/jarvis/env` без печати содержимого;
5. валидирует и печатает отчёт «перенесено N из M, конфликты: …».
