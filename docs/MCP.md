# Инструменты MCP в Jarvis

MCP (Model Context Protocol) — общий способ подключать к ассистенту чужие
инструменты: файловые серверы, домашние скрипты, сервисы вроде GitHub или
«погоды». Jarvis умеет быть **клиентом** MCP: он подключается к серверам, а их
инструменты становятся действиями — точно такими же, как у обычных навыков
(права, подтверждения, журнал, переключатель в окне).

Никаких новых зависимостей для этого не нужно: протокол — это JSON-RPC 2.0, а
Jarvis говорит с серверами либо через stdin/stdout запущенного процесса, либо
HTTP-запросами. Всё это умеет стандартная библиотека Python.

## Как настроить

Настройки серверов лежат в отдельном файле рядом с `config.toml`
(Linux: `~/.config/jarvis/mcp.toml`, Windows: `%LOCALAPPDATA%\Jarvis\config\mcp.toml`).
Файл с подсказками создаётся сам при первом запуске `jarvis mcp`.

```toml
[mcp]
enabled = true
max_tools_per_server = 25   # больше — длиннее запрос к модели

# Сервер-программа: Jarvis сам её запускает
[[server]]
name = "files"
description = "Доступ к папке с документами"
command = "npx"
args = ["-y", "@modelcontextprotocol/server-filesystem", "/home/user/Documents"]
enabled = true
confirm = false        # спрашивать подтверждение перед каждым вызовом
timeout_seconds = 20
idle_seconds = 600     # через сколько секунд без обращений сервер гасится

# Сервер по адресу (Streamable HTTP)
[[server]]
name = "home"
url = "http://localhost:8080/mcp"
headers = { Authorization = "Bearer ${MCP_HOME_TOKEN}" }
```

Правила файла:

* у сервера должно быть имя (`name`) и либо `command` (программа), либо `url`;
* токены и ключи — **только ссылками** `${ИМЯ}` из переменных окружения или
  `.env`; значение прямо в файле Jarvis не примет и скажет об этом;
* `{home}`, `{state}` и другие подстановки путей работают как в `config.toml`.

## Команды

```bash
jarvis mcp                     # что настроено и какие есть инструменты
jarvis mcp --json              # то же машинным языком (без ключей)
jarvis mcp --reload            # перечитать файл после правки
jarvis mcp --call files.read_file --arg path=/home/user/notes.txt
jarvis mcp --tools             # только список инструментов
```

Вызов из `--call` идёт напрямую, без модели, — удобно проверить сервер.

## Как это работает в разговоре

Инструменты попадают в список действий, который видит модель (у каждого
действия в описании видно, какие аргументы нужны). Дальше модель может их
выбрать — но **только по имени**: команд и путей она не пишет, как и раньше.

Есть и путь без модели, для слабых машин и для случаев, когда модель недоступна:

```
вы: какие инструменты mcp
Jarvis: Инструменты MCP: серверов 1, инструментов 6.
        - fake.echo: Повторяет текст обратно
        - fake.sum: Складывает два числа (нужны аргументы: a, b)

вы: вызови инструмент fake.sum a=2 b=3
Jarvis: 5.0
```

Экономия памяти и запросов:

* серверы **не запускаются при старте**: если фразу разобрал обычный навык
  («который час»), MCP не поднимается вообще;
* подключение происходит только перед обращением к модели или при фразах про
  MCP («какие инструменты mcp», «вызови инструмент …»);
* сервер, к которому давно не обращались, гасится сам (`idle_seconds`);
* если сервер не ответил, попытка повторяется не чаще раза в минуту, а работа
  Jarvis не ломается — фраза просто уходит обычным путём.

## Безопасность

* **Аргументы видны в вопросе.** Всё, что уйдёт серверу, сначала показывается:
  «Вызвать инструмент «sum» сервера «fake»? Отправлю: a: 2; b: 3». Отказ — вызов
  не уходит.
* **Подтверждение по умолчанию** спрашивается там, где аргументы предложила
  модель, где инструмент помечен сервером как «меняет данные»
  (`destructiveHint`) или где в настройках сервера стоит `confirm = true`.
  Если вы сами набрали «вызови инструмент fake.sum a=2 b=3», переспрашивать не
  о чем — аргументы уже ваши.
* **Секреты не печатаются**: в журнал и в окно попадают только имена серверов,
  названия инструментов и имена аргументов.
* **Аргументы от модели — только простые значения** (число, строка, да/нет),
  не длиннее 400 символов и не больше восьми; вложенные объекты отбрасываются.
  Обычным действиям Jarvis аргументы от модели не передаёт вовсе.
* **Разрешение навыка** — «Инструменты MCP» видно в окне на вкладке «Навыки»
  (там же список серверов и число инструментов) и можно выключить одним
  переключателем: тогда модель их не увидит.

## Что проверено

`tests/test_mcp.py` поднимает **настоящий** подставной сервер MCP отдельным
процессом (`tests/fake_mcp_server.py`) и проходит весь путь: разбор `mcp.toml`
(включая запрет хранить токен в файле), рукопожатие, список инструментов,
вызовы, ошибки инструмента, таймаут, падение сервера, HTTP-транспорт с ответом
в JSON и в SSE, подтверждение с аргументами, отказ, выключение навыка и работу
без модели. Команда `jarvis mcp` тоже проверяется целиком
(`tests/test_cli.py`, класс `McpCommandTests`).

## Чего пока нет

* **ресурсов и готовых подсказок** MCP (`resources/*`, `prompts/*`) — пока
  только инструменты (`tools/*`); этого достаточно для «сделай что-нибудь»;
* **уведомлений от сервера** (`notifications/*`): Jarvis их не показывает, но и
  не падает на них;
* **стриминга частичных результатов** (`progress`) — ответ ждём целиком;
* **своих серверов** Jarvis не отдаёт: он клиент, а не сервер MCP.

Всё перечисленное — отдельные шаги, их можно добавить, если понадобится.
