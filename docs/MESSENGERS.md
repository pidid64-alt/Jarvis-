# Сообщения: Telegram, почта, WhatsApp

Этот документ описывает пятый этап работы: Jarvis **отправляет** сообщения по
просьбе («отправь в телеграм маме: я дома») и **читает входящие**, чтобы
уведомить о них. Всё сделано на стандартной библиотеке Python: дополнительных
пакетов устанавливать не нужно, лишних процессов Jarvis не держит.

Идея простая: канал умеет только «отправить» и «что нового», а решения
(кому, что, спрашивать ли подтверждение) принимает ядро и навык.

---

## Что уже работает

| Канал | Отправка | Входящие | Как устроено |
| --- | --- | --- | --- |
| Telegram | да | да | Bot API: `sendMessage`, `getUpdates` (без вебхука и публичного адреса) |
| Почта (Gmail и любой IMAP/SMTP) | да | да | `smtplib` (465/STARTTLS) и `imaplib`, только чтение ящика |
| WhatsApp | да | да | программа **wacli** (привязка телефона по QR-коду), Jarvis говорит с ней по JSON |

Проверка состояния и пробная отправка из терминала:

```bash
jarvis messengers                      # каналы, адресная книга, подсказки
jarvis messengers --inbox              # что нового прямо сейчас
jarvis messengers --qr                 # как связать WhatsApp
jarvis messengers --channel telegram --to "Артём" --text "привет"   # спросит подтверждение
jarvis messengers --json               # то же состояние в виде JSON
```

В окне: раздел **Навыки** → карточка «Сообщения» (состояние каналов и кнопка
«Проверить входящие») и раздел **Настройки** → группа «Сообщения».

## Настройка

### 1. Включить сообщения

Настройки → «Сообщения» → **«Разрешить сообщения»** (`messengers.enabled = true`).
Пока это выключено, Jarvis откажется и отправлять, и читать.

Рядом полезные переключатели:

* «Уведомлять о входящих» (`notify`) — показывать системное уведомление о новом
  сообщении;
* «Проверять входящие, с» (`poll_seconds`, по умолчанию 60) — как часто демон
  опрашивает каналы.

### 2. Telegram

1. В Telegram откройте **@BotFather** → `/newbot` → получите токен вида
   `123456789:AA...`.
2. Настройки → «Сообщения» → поле **«Токен бота Telegram»** → вставьте токен →
   «Сохранить ключ». Значение уедет в `.env` как `JARVIS_TELEGRAM_TOKEN`, а в
   `config.toml` появится ссылка `${JARVIS_TELEGRAM_TOKEN}` — так и задумано,
   в файле настроек ключей не бывает.
3. Напишите своему боту любое сообщение (боты не могут писать первыми) — после
   этого Jarvis сможет отвечать в этот чат.
4. Узнать свой `chat_id` можно у бота **@userinfobot**; впишите его в
   `contacts.toml` рядом с именем человека.

Вручную (то же самое без окна):

```bash
jarvis secret set JARVIS_TELEGRAM_TOKEN      # значение не печатается
# в config.toml:  telegram_token = "${JARVIS_TELEGRAM_TOKEN}"
```

### 3. Почта (Gmail)

Обычный пароль Google не подойдёт и хранить его нельзя. Нужен **пароль
приложения**:

1. Включите двухэтапную аутентификацию в аккаунте Google.
2. Google → «Безопасность» → «Пароли приложений» → создайте пароль для «Почта»
   (16 символов).
3. Настройки → «Сообщения»: **«Адрес почты»** (`JARVIS_GMAIL_USER`) и
   **«Пароль приложения Google»** (`JARVIS_GMAIL_PASSWORD`).
4. Проверка: `jarvis messengers` покажет «почта: готов — вход выполнен».

Работает не только с Gmail: адреса серверов `smtp_host`, `smtp_port`,
`imap_host` и папка `mailbox` задаются в `config.toml`. Jarvis **не помечает
письма прочитанными** — ящик открывается в режиме «только чтение».

### 4. WhatsApp — через wacli (как в OpenClaw)

WhatsApp не даёт официального способа писать от себя без бизнес-аккаунта Meta,
поэтому Jarvis использует отдельную программу
[**wacli**](https://github.com/openclaw/wacli) — она привязывается к вашему
телефону как «связанное устройство» (тот же путь, что у OpenClaw).

1. Поставьте wacli: `brew install openclaw/tap/wacli` (macOS), готовые архивы
   для Windows/Linux — в разделе Releases, из исходников — Go 1.27+.
2. Свяжите телефон: `wacli auth` и отсканируйте QR в WhatsApp → «Связанные
   устройства» → «Связать устройство».
3. Проверьте: `jarvis messengers --qr` подскажет шаги, `jarvis messengers`
   покажет «whatsapp: готов». Если программа называется иначе, укажите путь в
   настройке `messengers.whatsapp_command`.

**Честно о рисках.** wacli работает по протоколу WhatsApp Web и не связан с
WhatsApp/Meta. За использование таких программ номер теоретически может
получить ограничение — поэтому для привязки лучше отдельный номер, а не
основной. Jarvis сам ничего не отправляет: перед каждой отправкой спрашивается
подтверждение с текстом сообщения.

Лицензия wacli — MIT, автор проекта не связан с WhatsApp/Meta. Благодарность и
ссылка есть в README и в окне «О программе».

## Адресная книга

Кому Jarvis может писать, написано в файле `contacts.toml` рядом с настройками
(точный путь покажет `jarvis messengers`). Он создаётся автоматически из
шаблона `jarvis/config/contacts.example.toml`.

```toml
[[contact]]
name = "Артём"
telegram = "123456789"        # chat_id
email = "artem@example.com"
whatsapp = "+77001234567"     # телефон или имя чата в WhatsApp

[[contact]]
name = "Мама"
telegram = "987654321"
```

Имена сравниваются с учётом падежей: «Артёму», «артему» и «Артём» — один
человек. Если под имя подходит несколько записей, Jarvis **переспросит**, а не
выберет наугад. Телефон, адрес почты и `chat_id` можно называть прямо во фразе —
они принимаются как есть.

## Правила отправки (взяты у скилла OpenClaw)

1. Нужны **получатель** и **текст**: «отправь в телеграм Артёму: привет».
   Чего-то нет — Jarvis задаёт уточняющий вопрос и показывает, кто есть в книге.
2. Перед отправкой всегда показывается вопрос: «Отправить в Telegram — Артём:
   «привет»?». Отказ — ничего не уходит.
3. При неясности получателя Jarvis не угадывает: несколько похожих чатов в
   WhatsApp — покажет их список.
4. Входящие Jarvis только читает и уведомляет. Он **не отвечает** на них
   сам — это отдельное решение человека.
5. Секреты не попадают ни в ответы, ни в журнал, ни в окно: в сообщениях о
   состоянии видны только имена переменных (`JARVIS_TELEGRAM_TOKEN`).

## Что где лежит

```
jarvis/providers/messengers.py   каналы: Telegram, почта, WhatsApp (wacli)
jarvis/core/messengers.py        адресная книга, состояние, проверка входящих
jarvis/skills/messengers/        навык: фразы, разбор «кому и что», подтверждение
jarvis/config/contacts.example.toml   шаблон адресной книги
```

Состояние (до какого обновления дочитали, какие входящие уже показаны) хранится
в `state/messengers.json` рядом с журналом. Последние входящие Jarvis показывает
один раз — повторно «новых сообщений нет», пока не придут следующие.

## Память и нагрузка

Отдельных процессов у Jarvis нет: Telegram и почта — обычные сетевые запросы,
WhatsApp — вызов программы wacli на время команды. Входящие опрашиваются не
чаще `poll_seconds` (по умолчанию раз в минуту), в окне состояние каналов
берётся без обращения к сети — окно открывается мгновенно.

## Чем проверено

`tests/test_messengers.py` — 100 с лишним проверок без сети: подставной
HTTP-клиент Telegram (включая ошибку «Unauthorized»), подставные `imaplib` и
`smtplib` (в том числе письмо без указания кодировки в заголовке), настоящий
файл-скрипт вместо wacli, разбор имён в падежах, отмена отправки, уведомление о
входящем один раз, состояние в `jarvis messengers --json` и запрет печатать
секрет.
