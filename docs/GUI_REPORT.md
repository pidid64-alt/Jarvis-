# Новое окно Jarvis: Tkinter заменён на локальную страницу

Отчёт по замене интерфейса. Дата: 07.10.2026. Ветка `arena/2cac497d-jarvis`.
Прошлое состояние: окно на Tkinter (`jarvis/interfaces/gui.py`) — по вашему
решению убрано вместе с треем (`pystray`).

---

## 1. Что теперь вместо Tkinter

Окно — это **страница самого Jarvis**, которую раздаёт ядро по адресу
`127.0.0.1` (случайный порт + случайный токен), а показывает её браузер в режиме
приложения (`--app`): без вкладок, адресной строки и поиска, со своей иконкой.
Снаружи это обычное окно с заголовком «Jarvis».

Почему так, а не библиотека окон:

| Вариант | Цена | Итог |
| --- | --- | --- |
| PySide6/Qt | 648 МБ колёс + 7 системных библиотек | не для 4 ГБ и не ставится «просто так» |
| ttkbootstrap | 3.8 МБ / 205 файлов | это тот же Tkinter, только с темой |
| customtkinter | 1.8 МБ / 96 файлов | тоже Tkinter под капотом, ваши претензии остаются |
| **локальная страница + браузер в режиме `--app`** | **0 МБ, ни одной новой зависимости** | **выбрано** |

Что это даёт по вашим требованиям:

* **легко для 4 ГБ** — новый код не добавляет ни одного процесса и ни одного
  мегабайта зависимостей: окно показывает браузер, который уже открыт в системе;
* **нет Tkinter** — он больше не участвует ни в запуске, ни в тестах, ни в стиле;
* **одинаково на Linux и Windows** — страница одна и та же, отличается только
  имя браузера;
* **читаемо при масштабе 125 % и 150 %** — размеры заданы в CSS-пикселях
  (текст 15 px, заголовки 17–21 px), браузер сам масштабирует всё окно целиком;
  это принципиально другой механизм, чем у Tkinter, где шрифт оставался мелким;
* **стиль не разъезжается** — палитра и шкалы берутся из прежнего
  `jarvis/interfaces/theme.py` (тема Fluent 11, Этап 1) и повторяются в CSS; за
  совпадением следит тест.

Секреты: страница и её файлы не содержат значений ключей; ключ вводится в
скрытое поле, уходит прямо в `.env`, а обратно показывается только маска.
Токен приходит в адресе `?token=…`, страница переносит его в память вкладки и
**убирает из адресной строки**. Все запросы к ядру требуют токен.

## 3. Как это запускать

```bash
python3 -m jarvis gui                 # поднимет ядро (если нужно) и откроет окно
python3 -m jarvis gui --tab           # то же, но обычной вкладкой в браузере
python3 -m jarvis gui --browser=edge  # каким браузером открыть
python3 -m jarvis gui --print-url     # только напечатать адрес (если браузера нет)
python3 -m jarvis gui --no-daemon     # не поднимать ядро, только открыть окно
```

Браузеры, которые умеют режим приложения (проверяются по очереди): Edge, Chrome,
Chromium, Brave, Vivaldi, Opera. Если ни одного нет — откроется браузер по
умолчанию обычной вкладкой; интерфейс от этого не меняется.

Горячие клавиши внутри окна: `Ctrl+L` — слушать, `Ctrl+Enter` — отправить,
`Esc` — отказ от подтверждения.

## 4. Как это проверено (без браузера в песочнице)

Браузера в песочнице нет, поэтому проверка сделана так:

1. **Файлы и раздача по HTTP** — `tests/test_webui.py`: страница и её файлы
   отдаются с правильными типами, незнакомый файл → 404, обращение с `..` не
   выходит за каталог, файлы интерфейса доступны без токена, а данные ядра —
   только с токеном. Страница не тянет ничего из интернета, в ней нет CDN и
   фреймворков.
2. **Стиль** — тест сверяет, что цвета и шкалы в `app.css` совпадают с
   `theme.py` (18 цветов × 2 темы + отступы + шрифты). Если поменять цвет только
   в одном месте — тест падает.
3. **Страница целиком, живьём** — `tests/js/smoke.js` исполняет настоящий
   `app.js` в node поверх настоящего API (крошечный подставной DOM в
   `tests/js/dom.js`, ~48 запросов к ядру за прогон, 30 проверок):

   * чат: приветствие, история, отправка «сколько времени» → ответ «Сейчас …»;
   * опасное действие: «перезагрузи компьютер» → окно подтверждения с вопросом,
     отказ закрывает окно, в чате ничего не теряется;
   * навыки: 10 карточек, примеры фраз, права, 10 переключателей, переключение
     доходит до ядра и возвращается обратно;
   * настройки: 12 строк, поле ключа скрыто, значение ключа в поле не
     подставляется, тема переключается на лету, сохранение отчитывается;
   * журнал: записи, фильтр по уровню, «скопировать для отчёта»;
   * «О программе»: версия, адрес ядра, пути.

   Это ловит опечатки в именах полей API, к которым некому придраться вживую —
   и уже поймало две ошибки (см. раздел 6).

4. **Node-тесты чистых функций** — подписи, тема, уровни журнала, классы
   сообщений, разбор имени ключа из `${ИМЯ}`, набор изменённых настроек.
5. **Весь набор тестов** — `231 passed, 116 subtests passed` (было 250: 40
   тестов старого окна убраны вместе с ним, 21 добавлен про новое окно).

Что проверено **не** было и почему: как страница выглядит в настоящем браузере
(в песочнице нет браузера и его нельзя скачать) и как она себя ведёт при
масштабе 125/150 % Windows. Для этого — предпросмотр (раздел 5) и ваша машина.

## 5. Предпросмотр

Пока вы читаете отчёт, в песочнице запущен **демонстрационный стенд**: то же
ядро и та же страница, что на вашей машине, только с пустым `.env` (ключа модели
нет) и без микрофона. Открывайте ссылку предпросмотра — страница с токеном
откроется сразу.

Что можно проверить руками:

* **Главная** — напишите «сколько времени» и нажмите «Отправить»: ответ даст
  локальный навык, модель для этого не нужна. Рядом — точка состояния и чипы
  провайдеров.
* **Навыки** — 10 карточек, переключатели, примеры фраз и права.
* **Настройки** — группы, тема (переключается сразу), поле ключа.
* **Журнал** — события и «Скопировать для отчёта».
* **О программе** — версия, пути, лицензии.
* Попробуйте «перезагрузи компьютер» — появится окно подтверждения (в стенде
  отвечайте «Отмена»: это общая песочница).

Стенд включается переменной окружения `JARVIS_DEMO_UI=1` (в обычной жизни не
нужен и выключен): корень сервера сразу перенаправляет на страницу с токеном.
Чтобы на вашем компьютере ничего не менялось — стенд живёт только здесь.

## 6. Что нашлось и починено по ходу

### Главное: окно подтверждения висело на экране с самого запуска

Ваш второй скриншот («нажал подтвердить — ничего не происходит, отмена тоже не
нажимается») помог найти ошибку, которую в песочнице было не видно: браузера-то
здесь нет.

Причина: у окна подтверждения в стиле задано `display: grid`, а кнопки «Стоп» —
`display: inline-grid`. Правила страницы **сильнее** встроенного правила браузера
`[hidden] { display: none }`, поэтому атрибут `hidden` на них не действовал:
окно подтверждения показывалось сразу при открытии окна ассистента (пустое,
потому что код его не открывал), закрывало весь интерфейс затемнением, а кнопки
в нём хотя и нажимались, но окно не исчезало — всё выглядело зависшим.
Кнопка «Стоп» точно так же висела рядом с полем ввода всё время.

Исправлено: в стиль добавлено правило `[hidden] { display: none !important; }`
с пояснением, почему оно нужно. Заодно убрано размытие фона у затемнения
(`backdrop-filter`) — оно дорого на слабой видеокарте и пользы почти не даёт.

Почему это не поймали тесты: подставной DOM для прогона страницы не считает CSS.
Теперь на это есть две проверки: одна следит, что правило `[hidden]` на месте,
вторая — что ни один элемент, который скрипт прячет через `hidden`, не остаётся
видимым из-за оформления. Плюс прогон страницы проверяет, что окно
подтверждения закрыто сразу после запуска.


1. **Голос в статусе отдавался как ссылка на функцию.** В `Providers` у
   `voice_enabled` не было `@property`, поэтому в `/status` уезжала строка
   `<bound method …>` вместо «да/нет». Это ломало индикатор голоса во всех
   интерфейсах. Исправлено, добавлены два теста-сторожа.
2. **Токен не попадал в первый запрос страницы.** Поле токена читалось один раз
   при создании объекта, а токен приходит в адресе уже после — первая загрузка
   осталась бы без данных («нужен заголовок X-Jarvis-Token»). Поймал прогон
   страницы в node, исправлено: токен берётся при каждом запросе.
3. **Имя ключа было вписано в страницу жёстко.** Теперь имя берётся из ссылки
   в настройках: `${МОЙ_КЛЮЧ}` сохранится под своим именем, а не под
   `JARVIS_LLM_KEY`.
4. Заодно: запасной способ передать токен (в адресе), если посредник срежет
   нестандартный заголовок; подписи прав и поля ключа вынесены в общий словарь
   текстов.

Правка от 07.10.2026 (после вашего скриншота с окном «Подтвердите действие»):

* окно подтверждения **всегда** показывает, о чём спрашивают: если навык не дал
  текст вопроса, показывается пояснение, а не пустое место;
* в окне появилась строка **«Запрос: «…»»** — фраза, из-за которой спрашивают
  (её отдаёт ядро вместе с вопросом), так что решение видно по существу;
* повторное окно для того же запроса больше не открывается — раньше поздний
  ответ сервера мог вернуть вопрос и выглядело так, будто окно «залипло»;
* в разделе «О программе» появилась кнопка **«Остановить Jarvis»** (с тем же
  подтверждением): раньше окно закрывалось, а ядро продолжало работать, и
  выключить ассистента без терминала было нечем;
* из списка лицензий убран `pystray` — значок в трее больше не используется;
  добавлено, что окно показывает браузер, уже установленный в системе.

## 7. Память

Замер `python tools/measure_memory.py --repeat 2` (свой процесс на сценарий,
взято лучшее из двух):

| Сценарий | Память | Пик |
| --- | --- | --- |
| пустой Python (точка отсчёта) | 7.7 МБ | 7.7 МБ |
| одна команда в терминале | 17.1 МБ | 17.1 МБ |
| демон без голоса и автопроверок | 16.3 МБ | 16.3 МБ |
| ядро + локальный API | 24.2 МБ | 24.2 МБ |
| **ядро + окно (сервер интерфейса)** | **24.4 МБ** | **24.4 МБ** |

Вывод: **окно не добавляет Jarvis ни мегабайта сверх API** (+0.2 МБ на отдачу
файлов страницы), а браузер пользователь и так держит открытым. Для сравнения:
одно окно на PySide6 потребовало бы 648 МБ колёс плюс системные библиотеки.

Чего в замерах нет: памяти самого браузера — её даёт ваша система, Jarvis на неё
не влияет. И чисел старого окна на Tkinter: в песочнице Tkinter не установлен,
поэтому измерить его было нечем — это ограничение честно указывалось в отчёте
Этапа 1.

## 9. Что сознательно не сделано

  работу (быстрый доступ и вызов ассистента) делают горячая клавиша и окно.

* **Скриншоты в этом отчёте** — вместо них предпросмотр (раздел 5): в песочнице
  нет браузера, снять настоящую страницу нечем. Могу добавить картинки позже,
  если пришлёте скриншот с вашей машины — вставлю в отчёт и README.
* **Проверка масштаба 125/150 % Windows** — оставлена вам: механизм другой, чем
  у Tkinter, но подтвердить это можно только на Windows.
* **Плагин-иконки из чужих наборов** — не подключал: все иконки нарисованы
  вручную в самой странице (SVG), поэтому вопроса о лицензиях не возникает.
* **Этап 3 (тесты навыков, установка одной командой, `doctor`, README для
  обычных пользователей)** — не начинал, как и договаривались: он идёт после
  того, как вы примете окно.
