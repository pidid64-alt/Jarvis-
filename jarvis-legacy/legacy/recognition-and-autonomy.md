# Распознавание и автономный мониторинг

## Что изменилось

### Голосовые команды

- Единая нормализация регистра, `ё/е`, Unicode и пунктуации. «Джарвис, открой — дискорд, пожалуйста!» сопоставляется с «открой дискорд».
- Точные фразы ищутся по границам слов: «пароль» не совпадёт с «беспарольный».
- Для неточного сопоставления убираются обращения и «пожалуйста» по краям фразы. Учитывается не только лучший результат, но и отрыв от второй команды: неоднозначность означает отказ от запуска, а не выбор по порядку в JSON.
- Без LLM можно разобрать до четырёх неточно распознанных команд, соединённых «и», «потом», «затем», «а потом». Например: «открой дискор и какая пагода». Весь локальный план проверяется **до первого действия**. Неизвестная часть не должна молча теряться.
- Точный fast-path также не принимает содержательные слова вне найденных команд. Лимит `exact_max_extra_words` теперь относится к словам-связкам и обращениям, а не к произвольному тексту.
- Фразы с отрицанием/отменой локально не исполняются: их разбирает LLM, если он доступен. Без него Jarvis просит повторить точнее. Это консервативное ограничение затрагивает и фразы вроде «не беспокоить в дискорде» — можно использовать другую фразу этой команды.
- Команды с `confirm: true` или тегом `dangerous` не выбираются нечётким сопоставлением. Подтверждение опасных команд обязательно на любом маршруте, включая точный. Ответы «да нет» и «давай не надо» больше не считаются согласием.

Порядок маршрутов: точное локальное совпадение → опциональный LLM → локальный нечёткий план. LLM по-прежнему получает только описание whitelist, не право генерировать shell-команды.

### Запись и Whisper

VAD требует несколько речевых кадров, сохраняет примерно 300 мс до начала речи и отбрасывает слишком короткие шумовые фрагменты. Частичные чтения аудиопотока собираются в целые кадры; зависший микрофон больше не блокирует запись бесконечно.

Whisper получает `temperature=0` и `temperature_inc=0` для воспроизводимого декодирования. Неречевые подписи («[Музыка]», «[Аплодисменты]» и т. п.) не передаются в обработку команд. Можно задать короткую подсказку с именами приложений, но по умолчанию она выключена: слишком сильная подсказка способна провоцировать выдуманный текст на шуме.

Это не новая акустическая модель. Реальное качество и задержку надо проверять на вашем микрофоне. Модель `base-q5_1` оставлена прежней, чтобы не увеличивать нагрузку и расход памяти.

## Настройки распознавания — `config.json`

| Параметр | По умолчанию | Назначение |
|---|---:|---|
| `match_threshold` | `0.72` | Минимальная похожесть неточного совпадения; раньше было 0.6. Это эвристика, не вероятность правильного распознавания. |
| `match_ambiguity_margin` | `0.06` | Минимальный отрыв лучшей команды от второй. |
| `vad_start_speech_seconds` | `0.09` | Суммарная речь в окне начала записи для срабатывания VAD. |
| `vad_min_speech_seconds` | `0.18` | Минимальная суммарная речь для передачи записи в STT. |
| `vad_silence_seconds` | `0.9` | Пауза до завершения фразы. При обрезании медленной речи попробуйте 1.2. |
| `vad_aggressiveness` | `2` | 0–3; при тихой речи попробуйте 1, при шуме — 3. |
| `stt_no_speech_threshold` | `0.6` | Порог отсутствия речи, передаваемый whisper-server. |
| `stt_prompt` | `""` | Необязательный словарь, например `"Джарвис, Discord, Firefox, CachyOS"`, до 500 символов. |

Настройки `config.json` применяются после перезапуска `jarvis.service`. Фразы в `commands.json` перечитываются на каждом запросе. VAD требует `webrtcvad-wheels`; без него остаётся фиксированная запись, и фильтры речевых кадров не применяются.

Не снижайте общий порог ради одной команды: лучше добавьте проверенный вариант в её `phrases`. Совпадающие фразы у разных ID намеренно считаются неоднозначными.

## Автономность без облака

Все восемь стандартных правил `autonomy.json` имеют локальные условия: обновления, упавшие сервисы, температура CPU, место на диске, память, батарея, ошибки журнала и доступность интернета. Решение о предупреждении не требует LLM или API-ключа. Сами сетевые проверки, естественно, могут обращаться к сети.

`health_checks.py` возвращает JSON с отдельно названными метриками:

- CPU: максимальная температура CPU из `sensors -j` (нужен `lm_sensors`; поддерживаются coretemp, k10temp, zenpower, cpu_thermal).
- Диск: минимальная доля **свободного** места на файловых системах `/` и домашнего каталога, без дублирования одного устройства.
- Память: доля занятой памяти через `MemAvailable` из `/proc/meminfo`, с учётом освобождаемого кеша.
- Батарея: минимальный заряд разряжающейся батареи; зарядка не вызывает предупреждение о работе от батареи.

Отсутствующие датчики и неизвестные метрики не считаются аварией. Числа из человекочитаемого текста, имена дисков и даты больше не склеиваются в одно значение.

### Расписание и уведомления

- Отметки запуска, последние уведомления и отложенные предупреждения хранятся в `~/.local/share/jarvis/autonomy_state.json`.
- Ежедневное правило выполняется после заданного времени, даже если компьютер пропустил нужную минуту из-за сна. За один день повторно не запускается.
- Каждая наступившая проверка выполняется независимо от ограничения частоты уведомлений. Предупреждения отправляются по очереди, старейшие первыми.
- `min_notify_interval_seconds` — интервал между отправками разных уведомлений, по умолчанию 300 секунд.
- `repeat_seconds` — повтор одного продолжающегося предупреждения, по умолчанию 21600 секунд (6 часов); колебания показателя не обходят этот интервал.
- `if_changed: true` — одинаковый текст повторно не сообщается, пока состояние не изменится или не вернётся в норму.
- В `quiet_hours` проверки продолжаются, но отправка и озвучка приостановлены. Время — локальное время машины. Исчезнувшая проблема удаляется из отложенных предупреждений при следующей проверке. Уже отправленные в inbox сообщения остаются до обработки.
- `enabled: false` в правиле отключает его. `autonomy.json` перечитывается каждый цикл, без рестарта.
- Inbox ограничен 50 записями. Отдельная файловая блокировка и подтверждение по ID предотвращают потерю новых сообщений при одновременной записи и озвучке. Повреждённый inbox сохраняется для диагностики, а не затирается.
- Jarvis читает inbox на простое, примерно раз в 120 секунд. Помимо голоса показывается уведомление рабочего стола.

### Граница автономности

Мониторинг **не чинит систему сам**, не удаляет файлы, не устанавливает обновления и не перезапускает сервисы. Для самостоятельного выполнения допускаются только заранее проверенные команды с `autonomy_safe: true` в `commands.json`; `speak_output` сам по себе разрешением не является. Команды с подтверждением или тегом `dangerous` исключены даже при наличии этого флага.

`autonomy_command` задаёт отдельную статическую команду для структурированного вывода. Без этого поля используется обычный `command`. Проверяйте оба поля вручную, прежде чем ставить `autonomy_safe`.

Для нового порогового правила укажите `metric` и `if_above`, `if_above_percent` или `if_below_percent`. Для текстовых проверок поддерживаются `if_equals` (полное совпадение), `notify_pattern`, `skip_patterns` и `has_keywords`. Правило без надёжного локального условия требует LLM; без него оно не делает догадок и не присылает предупреждение.

## Применение на установленном Jarvis

Выполните из каталога проекта на вашей CachyOS/Arch-машине. Штатные юниты и команды, как и раньше, ожидают установку в `~/jarvis`.

```bash
mkdir -p ~/.config/systemd/user
cp systemd/jarvis-autonomy.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable jarvis-autonomy.service
systemctl --user restart jarvis.service jarvis-autonomy.service
systemctl --user status jarvis.service jarvis-autonomy.service
```

При новой установке `install.sh` включает мониторинг автоматически.

Разовый прогон всех включённых правил (в том числе ежедневных):

```bash
venv/bin/python autonomy.py --once --debug
```

Это **не dry run**: выполняются read-only проверки, обновляется состояние и может добавиться уведомление. Тихие часы, дедупликация и интервал уведомлений сохраняются. За один прогон отправляется не более одного сообщения; остальные остаются отложенными для демона. Параллельные `--once` и демон сериализуются блокировкой.

Отключить мониторинг:

```bash
systemctl --user disable --now jarvis-autonomy.service
```

## Проверки разработчика

```bash
python3 -m venv .venv
.venv/bin/pip install requests
.venv/bin/python -m unittest discover -v
bash -n install.sh
python3 health_checks.py memory_usage
python3 health_checks.py disk_space
```

Тесты не требуют микрофона, LLM-ключа, systemd или работающих STT/TTS-серверов. Покрываются нормализация, неоднозначность, отрицания, подтверждения, локальные последовательности, VAD и частичные чтения, пороги, расписание, рестарт, тихие часы, whitelist и конкурентная очередь. Сквозную запись и распознавание проверяйте отдельно: `venv/bin/python jarvis.py --once --debug`.
