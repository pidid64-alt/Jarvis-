# Дизайн: подключение LLM-мозга Jarvis к OpenRouter

**Дата:** 2026-08-23
**Статус:** одобрено пользователем (вариант B, модель stealth/ox-alpha)

## Цель

Включить уже существующий, но никогда не работавший LLM-маршрут Jarvis
(`try_llm_route` → `parse_intent`): свободная речь распознаётся LLM и
превращается в выбор команды из whitelist, короткий голосовой ответ или
уточняющий вопрос. Старый matcher (`match_command`) остаётся автоматическим
fallback'ом.

Не входит в объём: параметризованные команды, многошаговые сценарии,
текстовый чат, Telegram.

## Текущее состояние (почему не работает)

- `config.json` указывает на OmniRoute `localhost:20128`, который лежит
  (connection refused с 17 августа 2026).
- Ключ передаётся через env `OMNIROUTE_API_KEY`, захардкоженный в двух
  systemd-юнитах (риск утечки в git при следующем коммите).

## Архитектура решения

```
голос → whisper → try_llm_route → https://openrouter.ai/api/v1
                       │             model=stealth/ox-alpha
                       │             ответ строго JSON {command|speak|ask}
                       ▼                        │
                 match_command      ◄── fallback при любой ошибке
```

Изменяется только конфигурация и доставка ключа. Логика jarvis.py,
llm_parser.py, llm_client.py не меняется: безопасность уже соблюдена
(LLM видит только id/tags/описания команд; id проверяется по whitelist;
распознанный текст никогда не попадает в shell).

## Компоненты

| # | Компонент | Действие |
|---|-----------|----------|
| 1 | `~/.config/jarvis/env` (новый, вне репо, chmod 600) | `OPENROUTER_API_KEY=sk-or-v1-…` |
| 2 | `config.json` | `base_url: https://openrouter.ai/api/v1` (заодно убрать ведущий пробел), `api_key_env: OPENROUTER_API_KEY`, `model: stealth/ox-alpha` |
| 3 | `systemd/jarvis.service`, `systemd/jarvis-autonomy.service` | удалить хардкод `OMNIROUTE_API_KEY=sk-…`, добавить `EnvironmentFile=%h/.config/jarvis/env` |
| 4 | `scripts/test_llm.sh` (новый) | прогон контрольных фраз через реальный API c замером задержки |
| 5 | `CLAUDE.md` | обновить раздел про LLM-слой (сейчас там «No Ollama/LLM required» — неправда) |

Ключ берётся из `~/.claude/settings.json` (`env.ANTHROPIC_API_KEY`,
формат `sk-or-v1-…`, провайдер OpenRouter) — копируется один раз в
`~/.config/jarvis/env`; сам settings.json не изменяется.

## Обработка ошибок

Уже реализовано в коде и остаётся без изменений:
- таймаут 8с, 1 ретрай (`llm_client.py`);
- `fallback_to_match: true` — любая ошибка LLM (сеть, ключ, битый JSON)
  молча валится на `match_command`;
- несуществующий id от LLM отбрасывается whitelist-проверкой
  (`_validate_action`), опасным командам принудительно ставится
  подтверждение.

## План тестирования

1. **parse_intent против живого API** (через test_llm.sh), контрольные фразы:
   - точная команда («какая погода») → command с корректным id;
   - свободная формулировка («а включи ютуб») → command;
   - болтовня («как дела?») → speak;
   - опасная («выключи компьютер») → command + needs_confirmation=true;
   - неизвестное намерение («завари кофе») → speak или ask.
2. **Замер задержки**: медиана ≤3с. Если выше — доложить пользователю с
   цифрами и вариантами (ужать промпт со списком команд, сменить модель).
3. **Fallback**: временно сломать ключ → убедиться, что voice-контур
   работает по match_command без ошибок для пользователя.
4. **Живой e2e**: пользователь произносит 2–3 фразы в микрофон.
5. Бонус-проверка: autonomy.py начал писать уведомления в inbox.json
   (правила оживают автоматически, т.к. читают тот же config.json).

## Риски

- Модель stealth/ox-alpha платная: списания с ключа пользователя.
  Каждый запрос несёт системный промпт со списком всех 323 команд
  (~3–4K токенов). Замер фактической стоимости/скорости на шаге 2.
- Если модель недоступна через /v1/chat/completions — проверить список
  моделей OpenRouter и согласовать замену с пользователем.
- Задержка большой модели может превышать комфортные для голоса ~2с —
  решение по итогам замеров.
