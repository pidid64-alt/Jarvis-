# Jarvis Control Core

Голосовое управление CachyOS-машиной: хоткей → запись → распознавание →
выполнение команды из белого списка → голосовой ответ. STT, TTS,
локальный разбор команд и мониторинг работают без облака. Для свободного
диалога и сложных запросов опционально используется внешний LLM.

**Обновление распознавания и автономности:** нормализация речи, защита от
неоднозначных команд, локальные последовательности, фильтрация короткого шума
и восемь автономных проверок без LLM. [Настройки и применение обновления](docs/recognition-and-autonomy.md).

```
Super+J ──────────┐
                   ▼
"Джарвис" → wakeword.py (SIGUSR1) → jarvis.py (демон) → whisper-server (STT, :8081)
                                          │                        │
                                          │                 распознанный текст
                                          ▼                        │
                                   commands.json  ◄────────────────┘
                                   (whitelist, fuzzy-match)
                                          │
                                          ▼
                                   выполнение shell-команды
                                          │
                                          ▼
                                   piper http_server (TTS, :5000)  →  paplay
```

Два независимых способа разбудить демон — хоткей и голос. Оба в
конечном счёте делают одно и то же: `kill -USR1 <pid jarvis.py>`.
Можно пользоваться только одним, оставить только хоткей (по умолчанию,
если не ставить wake-word) или держать оба сразу.

Ключевой принцип безопасности: **распознанный голосом текст никогда не
становится частью shell-команды**. Он только выбирает, какая из заранее
прописанных в `commands.json` команд запустится — сами команды всегда
статичны и написаны тобой заранее. Это тот же подход, что и в
whitelist-командах Литвина.

## Состав

| Файл/папка | Что это |
|---|---|
| `jarvis.py` | Демон-оркестратор: сигнал → запись → STT → matching → exec → TTS |
| `recognition.py` | Нормализация команд и буфер речевых кадров VAD |
| `autonomy.py`, `autonomy.json` | Автономные проверки, расписание, тихие часы и дедупликация |
| `health_checks.py` | Структурированные read-only метрики CPU, диска, памяти и батареи |
| `inbox_store.py` | Атомарная очередь уведомлений с межпроцессной блокировкой |
| `config.json` | Порты, язык, длительность записи, порог уверенности |
| `commands.json` | Белый список голосовых команд — редактируется на лету |
| `scripts/*.sh` | Хелперы для команд с «говорящим» выводом (статус, диск, IP) |
| `jarvis-trigger.sh` | Будит демон по хоткею |
| `wakeword.py` | Опционально: слушает микрофон фоново, будит демон по слову "Джарвис" |
| `wakeword_config.json` | Порог уверенности, кулдаун, путь к модели wake-word |
| `systemd/*.service` | 5 юнитов: whisper-server, piper-server, jarvis, autonomy, wakeword (опц.) |
| `install.sh` | Сборка whisper.cpp, установка Piper, systemd, хоткей, wake-word (если есть модель) |

## Установка

```bash
chmod +x install.sh
./install.sh
```

Скрипт идемпотентен — можно перезапускать, уже готовые шаги пропустит.
Что он делает:

1. Клонирует и собирает `whisper.cpp` (`cmake -B build && cmake --build build`),
   качает мультиязычную квантованную модель `base-q5_1` (~60МБ, понимает русский).
2. Ставит `piper-tts[http]` в venv, качает голос `ru_RU-dmitri-medium`.
3. Устанавливает `systemd --user` юниты и включает STT, TTS, Jarvis и автономный мониторинг.
4. Вешает `Super+J` на `jarvis-trigger.sh` через `xfconf-query`.

**Sudoers install.sh не трогает.** В конце печатает шаблон для
`sudo visudo -f /etc/sudoers.d/jarvis` — впиши только те команды, которые
реально спросили пароль при ручной проверке (restart NetworkManager,
poweroff, pacman -Syu — обычно да; suspend и lock — обычно нет, их
разрешает polkit для активной сессии).

## Проверка по шагам

```bash
# 1. Микрофон вообще пишет?
parecord --rate=16000 --channels=1 --format=s16le --file-format=wav /tmp/t.wav
# Ctrl+C через пару секунд
paplay /tmp/t.wav

# 2. Серверы подняты?
curl http://127.0.0.1:8081/health
curl -X POST -H 'Content-Type: application/json' \
     -d '{"text":"Проверка связи"}' http://127.0.0.1:5000/synthesize -o /tmp/r.wav && paplay /tmp/r.wav

# 3. Весь конвейер разом, без хоткея
venv/bin/python3 jarvis.py --once --debug
```

Логи демона: `~/.local/share/jarvis/jarvis.log`.
Статус сервисов: `systemctl --user status jarvis.service jarvis-whisper.service jarvis-piper.service`.

## Как добавить команду

В `commands.json` — новый объект в массиве `commands`:

```json
{
  "id": "my_command",
  "phrases": ["как ты сказал", "вариант фразы два"],
  "command": "твоя-shell-команда",
  "response": "Что сказать в ответ",
  "speak_output": false,
  "speak_before": false,
  "background": false
}
```

- `speak_output: true` — вместо/вместе с `response` озвучивается stdout
  команды (для команд-запросов вроде статуса).
- `speak_before: true` — `response` озвучивается **до** запуска команды
  (нужно для suspend/lock/poweroff/reboot/logout — иначе TTS не успеет
  договорить).
- `background: true` — команда запускается не дожидаясь завершения,
  ответ сразу; при завершении отдельно озвучится `done_message`.
- `min_score` — свой порог уверенности для конкретной команды, выше
  общего `match_threshold` (0.72 по умолчанию). Команды с `confirm: true`
  или тегом `dangerous` допускают только точное локальное совпадение
  и требуют отдельного подтверждения перед исполнением.

Файл перечитывается на каждый запрос — перезапуск демона не нужен.

### Matcher: защита от обрубленных фраз

Если сказано **меньше слов**, чем в целевой фразе — совпадение не
считается вообще, даже если похоже фонетически. Это защита конкретно
от случая, когда STT срезало объект команды: одно только "перезагрузи"
(без "сеть" или "компьютер") раньше могло случайно среагировать —
теперь просто не матчится ни на что, попросит повторить. Полностью
прозвучавшая целиком фраза даёт оценку 1.0, но отрицания и неоднозначные
совпадения не запускаются локально. Слова должны совпадать целиком, а
не как подстроки. [Подробности и параметры matcher/VAD](docs/recognition-and-autonomy.md).

## Wake-word: вызов по слову "Джарвис"

По умолчанию `install.sh` его не ставит — нужна отдельная модель под
конкретное слово, готовой на "Джарвис" в открытом доступе нет. Хоткей
`Super+J` при этом никуда не девается и работает как раньше, даже если
wake-word не настроен вообще.

### 1. Обучить модель (10-15 минут, без GPU нужен)

openWakeWord обучает лёгкие модели по нескольким текстовым/синтезированным
примерам слова, без записи своего голоса руками:

1. Открой их обучающий Colab-ноутбук — ссылка в репозитории
   [dscripka/openWakeWord](https://github.com/dscripka/openWakeWord)
   (`notebooks/automatic_model_training.ipynb`).
2. Впиши целевое слово `Джарвис` (можно и латиницей `Jarvis` — важно,
   чтобы совпадало с тем, как его чаще всего произносишь).
3. Запусти все ячейки — ноутбук сам сгенерирует TTS-примеры слова
   разными голосами, подмешает шум и обучит модель.
4. Скачай результат — файл `<имя>.tflite` (или `.onnx`).

### 2. Положить модель в проект

```bash
mkdir -p models/wakeword
cp ~/Downloads/jarvis.tflite models/wakeword/jarvis.tflite
```

Имя файла настраивается в `wakeword_config.json` (`model_path`), по
умолчанию ожидается ровно `jarvis.tflite`.

### 3. Поставить

```bash
./install.sh
```

Идемпотентен, как и раньше: если `models/wakeword/jarvis.tflite`
уже на месте, установщик сам поставит `openwakeword`, `sounddevice`,
`numpy` в venv и поднимет `jarvis-wakeword.service`. Если модели нет —
просто пропустит этот шаг, ничего не сломав.

### 4. Проверить

```bash
venv/bin/python3 wakeword.py --debug
```

Печатает `score=` для каждого окна аудио (~80мс) — говори "Джарвис" и
смотри, что score подскакивает к 1.0. Порог по умолчанию `0.5`
(`wakeword_config.json`, `threshold`) — если много ложных срабатываний
от похожих слов или фонового шума, подними до `0.6-0.7`; если не
слышит с первого раза — опусти.

Статус: `systemctl --user status jarvis-wakeword.service`.
Логи: `~/.local/share/jarvis/wakeword.log`.

### Как это работает под капотом

`wakeword.py` — отдельный резидентный процесс, никак не встроенный в
`jarvis.py`. Он не трогает распознавание команд, matching или
что-либо ещё в основном контуре — при детекте слова делает буквально
то же самое действие, что и `jarvis-trigger.sh`: `kill -USR1` в pid
из `~/.local/share/jarvis/jarvis.pid`. Дальше всё идёт как обычно —
демон просыпается, 4 секунды пишет команду, распознаёт, матчит,
выполняет.

Ресурсы: openWakeWord на CPU — это ~50-80МБ резидентно и почти нулевая
нагрузка в простое (короткие окна аудио, лёгкая модель). См. следующий
раздел про общий бюджет памяти на твоём железе.

## Железо и ресурсы

На твоём i3-10110U / 3.6ГБ это бюджетный набор: whisper-server с
`base-q5_1` ест по факту ~150-250МБ резидентно, piper-server с medium
голосом — ещё ~150-250МБ. Заметь: **этот контур не требует Ollama** —
для голосовых команд LLM не задействован вообще, так что он спокойно
живёт даже когда NOXY выключен. Если параллельно крутится
qwen2.5:3b под NOXY — последи за `free -h`; при нехватке варианты:
перейти на модель `tiny-q5_1` (~30МБ) или запускать whisper/piper
серверы по требованию вместо постоянного резидента (жертвуешь
секундой-двумя на холодный старт ради простоя без нагрузки).

Если ставишь wake-word поверх этого — плюс ~50-80МБ на `wakeword.py`
(openWakeWord, CPU, простаивающая модель почти не грузит ядро). Если
после этого станет совсем тесно, а слушать голосом обязательно —
можно оставить только хоткей и снять `jarvis-wakeword.service`
(`systemctl --user disable --now jarvis-wakeword.service`) вместо
компромиссов с whisper/piper.

## Команды из коробки

78 штук в `commands.json`: статус/диск/сеть/температура/батарея/порты/
пользователи/своп/zram/вентилятор/упавшие сервисы/ошибки в журнале/время
последней загрузки, сеть (вайфай вкл-выкл, список сетей, проверка
интернета, tailscale статус и IP, DNS), громкость и яркость, сессия
(лок/сон/ребут/логаут/пауэрофф), окна (открой/сверни/разверни/закрой/
сменить рабочий стол), буфер обмена, bluetooth, медиаплеер, пакеты
(обновления/кэш/сироты/AUR/npm/pip), grязные git-репозитории, файрвол,
докер, корзина, cpupower-режимы (performance/powersave — то же, что ты
уже тюнил руками), earlyoom-статус, новости (RSS-заголовки, источник —
`JARVIS_NEWS_FEED_URL`, по умолчанию Лента.ру), пара «характерных» реплик.

**Пять команд — шаблоны под твои реальные пути/сервисы, без правки не
заработают как надо:**

- `ollama_status` / `restart_ollama` — предполагают Ollama системным
  сервисом (`systemctl ... ollama`); если у тебя иначе — поправь.
- `rat_hunt_scan` — путь `$HOME/rat_hunt.sh`.
- `restart_litvin` — `systemctl --user restart litvin.service`; если
  бот не оформлен юнитом — замени на реальный способ рестарта.
- `restart_noxy` — аналогично, `systemctl --user restart noxy.service`.
- `git_dirty_repos` — по умолчанию ищет `.git` в `$HOME` на глубину 3;
  если проекты лежат не прямо в домашней папке, задай переменную
  окружения `JARVIS_GIT_SEARCH_DIRS` в юните `jarvis.service`
  (`systemctl --user edit jarvis.service` →
  `Environment=JARVIS_GIT_SEARCH_DIRS=/путь/к/проектам`).

## Что стоит доделать перед серьёзным использованием

- ~~Явный шаг подтверждения перед опасными командами~~ — **сделано**:
  команды с `confirm: true` в `commands.json` (сейчас `poweroff`,
  `reboot`, `logout`, `system_update`) сначала переспрашивают голосом
  («Точно выключить? Скажи да»), записывают второй ответ и выполняются
  только после «да»/«подтверждаю»/«давай». Тишина, любой другой ответ
  или недоступный STT = отказ. Текст вопроса — поле `confirm_prompt`.
- `pacman -Syu --noconfirm` без надзора по голосовой команде — удобно,
  но на Arch иногда требует ручного вмешательства (partial upgrades,
  конфликты). Решай сам, готов ли доверить это voice-triggered фоновому
  процессу, или убрать `--noconfirm`/`background` и делать вручную.
- ~~Запись фиксированной длины~~ — **сделано**: запись теперь через VAD
  (`webrtcvad`, ставится как `webrtcvad-wheels`): после триггера играет
  короткий сигнал «говори» (`beep_command` в config.json), затем демон
  ждёт начала речи (`vad_wait_speech_seconds`), пишет до
  `vad_silence_seconds` тишины после фразы, но не дольше
  `max_record_seconds`. Если речь не началась — отмена без обращения к
  whisper. Если пакет `webrtcvad` не установлен, работает старый режим
  с фиксированными `record_seconds`.
- Слияние с NOXY: сейчас matching в jarvis.py — чисто фразовый
  (`difflib`). Когда понадобится понимать команды в свободной форме —
  можно завернуть шаг matching в вызов уже поднятого Ollama
  (qwen2.5:3b) вместо/вместе с fuzzy-match, отдавая ему список id
  команд и текст, и просить вернуть JSON `{"command_id": ...}`.
